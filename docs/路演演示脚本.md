**点：首页 →「阅读完整品牌故事」**

> 成分不透明、包装难单手操作、价格虚高。我们做了三件事：**产地透明、成分极简、拒绝溢价**。"

**点：首页「为什么选择我们」数据区**

> "这是我们的调研数据：92.6% 的家长最看重成分天然无添加，78.5% 要求原料可溯源。
> 而我们 100ml 只卖 69 元，松达同品类是 78 元/30ml。"

**点：商品详情页往下滑到「价格对比」表**

> "我们把自己的 100ml 和松达 30ml、贝亲矿物油、农家散装油放在一张表里比，每 10ml 单价一目了然。"

## 第 2 幕 · 一物一码溯源（90 秒）★核心亮点

**点：底部「溯源」→「用示例码体验」**

> "每瓶油底部都有一个刮开涂层的二维码。扫码会做三件事：
> 第一，**验签**——二维码里嵌了基于椭圆曲线数字签名的密码学签名，复制二维码是伪造不出来的；
> 第二，**展示时间轴**——从这块油茶林的地块编号、经纬度、海拔，到采摘日期、压榨批次，
> 再到检测报告、无菌灌装，每个节点都能看到。"

**手指往下滑时间轴**

> "这里是**农户刘子祥**——这一瓶油具体是谁家种的山茶果。这是区块链式哈希链存证：
> 每个节点哈希 = SHA-256(前序哈希 + 节点内容)，任何一个节点被改，扫码就会报异常。"

**滚到「防伪与存证校验」卡片**

> "现在展示的是链尾哈希和 6 个节点的校验结果，全部通过。"

**再扫一次同一个码（返回再点一次）**

> "注意这里——第二次扫同一个码，系统会提示'该码已被查询 N 次'。
> 如果是你自己刚拆封的油却显示已被查询多次，就要警惕二次封装了。这就是我们说的**首次查询防伪**。"

**（可选，强调技术真实性）后台 →「溯源管理」→「运行溯源全链路自检」**

> "这是我们现场跑出来的自检结果：生成签名 → 扫码验签 → 重复扫码提示 → **篡改 token 被拒绝** → 哈希链校验，
> 六步全部真实执行，不是预置文案。"

## 第 3 幕 · AI 客服 + 医疗安全红线（90 秒）★差异化亮点

**点：底部「AI问症」**

**先输入（或点快捷问题）**：`产品有检测报告吗？安全吗`

> "它先做意图识别——这句话被判为'产品安全性'，直接给标准话术，并推送检测报告卡片。"

**再输入**：`宝宝3个月，脖子褶皱处发红两天了能用吗`

> "这是我们最被家长需要的能力。它没有直接说'能用'，而是先做**症状分级**：
> 判为'需要谨慎使用'，给出护理要点——勤换、清洁、干燥、隔离，皮肤完整才薄涂，破皮渗液要先就医。
> 而且它注意到我提到了'3个月'和'脖子'，会追问持续时间。"

**关键演示**：`宝宝发烧了，身上还有疹子，能涂这个油吗`

> "这是**医疗安全红线**。命中'发热'后，它立刻先建议就医，并明确说'在医生诊断前不要在皮疹处涂抹护肤油'，
> 同时把这次会话标记为需要人工跟进。**我们绝不让 AI 做医学诊断**——
> 规则引擎负责所有安全判断，即便接入了大模型，也只让模型润色话术、不参与症状结论。"

**再输入**：`你们这个太慢了，我要投诉`

> "最后是情感分析：识别到愤怒情绪，自动携带对话上下文转人工。
> 这就是项目书写的'AI 过滤常见问题 + 人工处理复杂客诉'。"

**（可选）后台 →「人工客服」** 展示会话已进入待处理列表，并可回复。

## 常见追问与回答

**Q：你们真的做了小程序吗？**
A：这是我们导出的标准微信小程序工程（`chayaya/miniprogram`，13 个页面），
用微信开发者工具可以直接导入预览；web 端是同一套代码的可验收形态。
拿到 AppID 后把 `app.js` 里的 `BASE_URL` 换成公网域名即可上架。

**Q：数据库用的什么？项目书里不是 MySQL 吗？**
A：项目书里写的是 MySQL + Redis。我们做了驱动抽象层，业务代码不感知具体数据库，
`DB_DRIVER=mysql` 一个环境变量就能切到 MySQL——现在这台演示机没装 MySQL，所以默认跑内置 SQLite，
建表语句由脚本从同一份 schema 自动转换成 MySQL DDL。部署到 ECS 时改环境变量即可。

**Q：溯源数据是你们自己填的，怎么保证真实？**
A：三层保证：一是数据由各环节责任人（农户、榨油坊、代工厂、品控）分别录入；
二是每个节点都做 SHA-256 哈希链存证，改一个节点后面全断，扫码即可验出；
三是接入联盟链/BaaS 后把哈希同步上链，中心库被改也无法通过链上比对。
现在演示的是本地哈希链版本，上链接口已预留。

**Q：AI 会不会乱说，把宝宝皮肤问题说成能用？**
A：不会。AI 只做两件事：识别意图、给非诊疗性护理建议。所有安全结论由规则引擎得出，
分为四级（可用/谨慎/患处禁用/先就医），命中发热、化脓、渗液、精神差等红线时先建议就医，
且此时会**跳过**大模型润色，避免安全措辞被改写。每条症状回答都带免责声明。

**Q：支付是假的吧？**
A：演示环境是模拟支付，避免产生真实资金流。真实接入只需把 `payOrder()` 里的分支
换成微信支付统一下单 + 异步回调，订单状态机与溯源码分配逻辑完全不用改。

## 演示故障预案

| 情况 | 处理 |
|---|---|
| 页面空白/接口报错 | 确认后端在跑：访问 `/api/health`；必要时 `npm run reset` 后重启 |
| 数据被前面演示改乱 | `npm run reset` 一秒恢复干净数据 |
| 网络不通（评审电脑） | 全流程离线可用：二维码、溯源、AI 客服均为本地实现，无需外网 |
| 无头演示不了"扫码" | 用溯源页的「用示例码体验」，或手动输入演示码（页面已列出） |
