## 三、这个地址的三个特性（要理解）

### 1. 地址是临时的，重启就变

Cloudflare 的「快速隧道」每次启动都会分配一个**新的随机域名**。
所以：**每次重启隧道，都要把新地址重新发给别人。**

如果你想固定地址 → 见第五节「升级为固定域名」。

### 2. 电脑关机就断

因为服务器就是你自己的电脑。要 24 小时在线 → 见第五节「正式部署」。

### 3. 二维码会自动适配

这是个技术细节，但很关键：

- 别人通过**公网地址**访问时，溯源页生成的二维码会指向**公网域名**→ 他用手机扫能打开
- 你自己通过**局域网/本机**访问时，二维码指向**局域网 IP**

实现方式：服务端从请求头（`x-forwarded-host` / `x-forwarded-proto`）推断"访问者正在用的地址"，
而不是写死一个配置。代码在 `backend/src/server.mjs` 的 `deriveBaseUrl()`。

## 四、日常操作命令

### 启动（两个终端，各跑一个）

```powershell
# 终端 1：启动后端（带访问口令）
cd chayaya\backend
$env:ACCESS_KEY="你的口令"
npm start

# 终端 2：启动公网隧道
& "C:\Program Files (x86)\cloudflared\cloudflared.exe" tunnel --url http://127.0.0.1:8788
```

隧道启动后，终端里会打印这样一段：

```
|  Your quick Tunnel has been created! Visit it at:  |
|  https://xxxx-xxxx-xxxx.trycloudflare.com          |
```

**把这个地址复制下来发给别人。**

### 停止

| 想停什么 | 怎么做 |
|---|---|
| 只停公网访问 | 关掉隧道那个终端（Ctrl+C），本机仍可用 |
| 全部停止 | 两个终端都 Ctrl+C |
| 恢复演示数据 | 在 backend 目录执行 `npm run reset` |

### 不想要口令了？

启动后端时**不设置** `ACCESS_KEY` 即可：

```powershell
cd chayaya\backend
npm start          # 不加 $env:ACCESS_KEY
```

## 五、升级路径（时间充裕时再做）

| 需求 | 方案 | 成本 |
|---|---|---|
| 地址固定不变 | 注册 Cloudflare 账号 → 用**命名隧道**（named tunnel）绑定你的域名 | 免费（域名需自己有） |
| 电脑关机也能访问 | 部署到云服务器（阿里云/腾讯云轻量应用服务器） | 约 100 元/年 |
| 前端永久在线 | 前端放 **GitHub Pages**（免费 HTTPS），后端放服务器 | 免费 + 服务器费用 |
| 微信里当小程序用 | 注册微信小程序拿 AppID → 导入 `chayaya/miniprogram` | 免费（个人主体） |

**关于 GitHub Pages 的注意点**（容易被误解）：
它只能托管**静态文件**，跑不了 Node.js 后端。所以：
- 只放前端 → 页面能打开，但所有数据加载失败（商品、溯源、AI 客服全依赖后端 API）
- 正确用法是：**前端放 Pages + 后端放服务器**，两边配合

## 七、常见问题

**Q：别人说打不开怎么办？**
按顺序检查：
1. 你的电脑是否开机且没睡眠
2. 隧道终端是否还在运行（关掉就断）
3. 后端终端是否还在运行
4. 地址是否复制完整（`https://` 开头，结尾没有多余字符）
5. 让对方**换个网络**试（有些校园网/公司网会拦隧道域名）

**Q：手机微信里打开提示"非官方网页"或打不开？**
微信内置浏览器对 `trycloudflare.com` 有时会拦截。让对方点右上角「···」→「在浏览器打开」。

**Q：能不能同时给很多人用？**
可以，但这是你电脑在做服务器，人多了会慢。演示场景（几个人到几十人）没问题。

**Q：二维码扫出来打不开？**
- 让别人**通过公网地址访问后再生成二维码**（这样码指向公网域名）
- 或者你自己用公网地址访问一次，再截图给别人
- 溯源页有"用示例码体验"按钮，可以直接演示，不依赖真扫码

**Q：隧道地址变了，之前发出去的怎么办？**
重新发新地址。或者升级成固定域名（第五节）。
